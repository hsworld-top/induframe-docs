核对 AI 创建的数据配置 ​

AI 说“写好了”，可能指写了一段说明、改了源码文件，也可能是已经保存了平台配置。先分清交付对象，再到真实界面核对，不只看聊天回复。

开始前，确认仍在同一个组织和工程，并有该工程的查看或维护权限。

1. 先让 AI 交付可查的信息 ​

可以这样要求：

请说明本次是只修改源码，还是通过平台建模保存了配置。
已保存的请逐项列出：所属接入源、查询或单元名称、对象 ID、生成的数据点完整路径、报警名称。
分别说明哪些只是保存、哪些已执行或调试、哪些尚未验证。
保存成功但上下文同步失败时，先重新读取确认，不重复创建。
不要把临时样例、默认值或静态页面数据说成真实运行数据。

对象 ID 用于核对同名项，不必由新手手工拼接接口地址。交付信息不全时，先请 AI 补齐实际读取结果，不让它猜一个路径。

2. 不同成果去哪里看 ​

数据库工作台左侧的区域名称是 “查询”；下文“保存查询”指其中已经保存的查询项，不是另一个模块。可通过“筛选表或查询”定位，不需要到编辑器搜索 SQL 文件。

AI 完成的内容在平台哪里查看核对重点
SQL 查询工程管理 → 目标工程 → 数据中心 → 接入源 → 对应数据库连接 → 保存查询查询名称、SQL、参数、输出配置及是否生成点
SQL 等来源生成的数据点数据中心 → 数据点完整路径、来源、类型、当前值、质量和时间
计算单元数据中心 → 计算单元 → 搜索并打开对应单元输入点、脚本、触发方式、输出及启用状态
报警配置数据中心 → 报警单元 → 查找对应报警关联点、条件、级别、启用及恢复设置
页面组件或源码文件应用开发 → 编辑器；随后打开“页面”文件差异、真实取数、工程用户权限
正式运行变化运维管理 → 工程部署与运维记录实际模式、版本、环境、任务与健康状态

计算、报警并不都显示成一个同名数据点。计算输出可生成点；报警要回报警单元查看配置，不能只在数据点列表搜索报警名称。

3. 用“AI 参与过”找到点，再返回来源 ​

  1. 进入 “数据中心” → “数据点”。
  2. 在显示 **“全部编写来源”**的下拉框（配置编写来源）中选择 “AI 参与过”。
  3. 配合名称、路径或来源筛选找到本次对象。
  4. 点击“查看详情”，核对来源与“开发态当前值”。
  5. 使用来源入口返回对应接入源或计算单元，检查实际配置。

“AI 参与过”表示平台记录了 AI 参与创建或修改，不是 AI 独占创建、审核通过或测试合格的标记。手工照抄 AI 给的 SQL，不会仅因文字来自 AI 就自动出现标记。

这个筛选位于数据中心的数据点列表，不要在所有计算、报警或应用开发列表中寻找同名筛选。没有标记时，仍按 AI 返回的真实名称、路径和来源查找，不立即判断成果丢失。

4. AI 写了 SQL，但列表里没有数据点 ​

先到对应连接的保存查询查找，不要立刻新建同名项。

  • 只有 SQL 文本或一个源码文件：尚不能证明已经保存查询。
  • 保存了查询：检查“输出配置”，查询保存不等于点已生成。
  • 已执行 SQL：结果表不等于可供页面调用的数据点。
  • 已生成点：复制输出路径，再到数据点列表核对；查看“数据预览”时辨认真实值与配置预览。

详细步骤见用 SQL 查询生成数据点。需要一个数值供计算或报警使用时，检查提取后的类型，不把完整结果集对象当作一个数字。

5. 从开发验证走到运行验证 ​

具体操作见计算单元、报警配置和SQL、计算与报警联动示例。

先核对源配置与点位，再检查计算、报警和页面。开发态默认值、样例消息或调试成功，不代表正式部署正在持续处理真实数据。

正式使用时按工程发布、更新部署流程明确提交新内容；“重新部署”只是重下发当前制品，不会自动采用最新开发配置。

保存已确认但同步失败时，先使用工作区 “同步工程上下文”，让 AI 重新读取实际对象，不重复创建。

结果不明确时 ​

开发中正确、线上没有变化时，继续按数据链路运行排查检查版本、部署和引擎，不直接重建配置。

清除筛选、核对工程与连接、刷新已有对象，再查看具体错误和运维记录。停止 AI、删除对话或切换分支不会撤销已经保存的平台配置。
