管理接入源与测试连接 ​

本文帮助你保存一个接入源、确认它的连接参数，并找到下一步业务验证入口。测试连接成功不代表查询、订阅或持续采集已经可用。

开始前 ​

  • 已从平台公共入口登录，并有目标工程的数据中心访问与编辑权限。系统管理员、工程管理员和运维管理员仍受工程归属和可见范围约束。
  • 工程当前允许开发，打开数据中心后没有占用、过期或权限错误。遇到这些提示，先恢复合法的工程访问，不要反复提交连接。
  • 外部数据源已就绪，已取得它的地址、端口、数据库或服务名称以及所需凭据。测试时优先使用受控模拟器或测试数据库，不向真实设备试写。
  • 需要 TLS 时，已确认服务端身份和可信 CA。若服务端要求客户端证书，还需要相互匹配的客户端证书与私钥。

账号与入口有疑问时，先看登录与退出和入口与账号。

进入列表并找到连接 ​

  1. 在工程列表打开目标工程的数据中心，选择接入源。
  2. 输入连接名称搜索，或选择类型筛选：全部、内置运行库、数据库、消息/流。
  3. 根据需要切换卡片视图与列表视图。连接较多时，可选择分页容量或自动容量，再逐页查看。
  4. 从某个连接的工作台返回列表时，使用返回接入源。不要把整页浏览器刷新当作保留当前搜索条件的方法。

确认当前工程和连接名称后再执行操作。另一个工程中的同名连接不是同一条记录。

新建并测试外部连接 ​

  1. 点击新建连接，选择实际使用的数据源类型。
  2. 填写连接名称及该类型的连接参数。名称最多 100 个字符，同一工程内不能重名。
  3. 对支持连接测试的类型，点击测试连接，查看本次成功或失败提示。修改地址、认证、TLS 或拓扑后，应重新测试。
  4. 点击创建连接。弹窗关闭后，在列表中确认新连接存在；如已执行保存后的验证，再查看最新测试摘要。
  5. 用该连接的工作台进行一次实际业务验证，不要停在连接测试成功这一步。
类型应核对的参数连接测试之后
MySQL、PostgreSQL、SQL Server主机、端口、数据库、用户名、密码及当前类型可见的 TLS / 高级参数在对应工作台验证实际查询与数据读取权限
Redis单机 / 哨兵 / 集群、节点地址、数据库编号、认证；哨兵的主节点名称在工作台查找并读取受控 Key；集群只使用数据库 0
MQTTmqtt / mqtts / ws / wss、地址、独立端口、认证及客户端参数在工作台验证所需的订阅或发布权限
Kafkabroker 地址、安全协议、SASL 机制与认证、TLS 材料在工作台保存消费规则并拉取真实主题样本
TDengine主机、端口、库名、认证、时区及 TLS 选择在工作台验证实际查询
HTTP、WebSocket连接名称等基础信息；具体请求或会话在工作台配置没有通用测试连接按钮，分别验证实际请求或短时会话

内置的关系库、时序库、实时库、消息中心不需要外部服务地址，也没有通用连接测试。请到对应工作台确认准备状态和所需业务操作；不要将打开入口等同于全部业务已经验收。

MQTT 地址与 TLS ​

  • UI 的传输选项是 mqtt、mqtts、ws、wss。WebSocket 路径属于地址路径，端口填写在独立端口字段，不追加到路径末尾。
  • 切换协议会应用该协议的默认端口。使用自定义端口时，切换后重新核对地址、端口及路径，再测试。
  • 加密不等于服务端身份验证。需要校验证书时，显式开启并核对服务端验证选项，提供可信 CA；不要通过关闭校验来掩盖错误 CA、主机名或过期证书。

编辑连接与保留凭据 ​

  1. 在目标连接上选择编辑，核对类型及原有公开参数。
  2. 已保存的密码和证书不会作为普通公开字段回填。留空表示保留原材料；输入新值后再清空，也不要当作已删除服务端秘密。
  3. 如需查看已保存密码，使用界面提供的查看入口。查看秘密与保存、测试连接不是同一种权限；被拒绝时不要从日志或共享文件取回秘密。
  4. 修改参数后重新测试，点击保存修改，再确认列表与已保存连接的验证结果。
  5. 如确实要清除秘密，只使用当前表单明确提供的清除操作；没有该操作时，不要猜测清空输入即可删除。

草稿测试使用当前表单的参数，不会单独更新已保存连接的测试摘要。编辑时保留的密码可能需要额外查看权限；保留的私有 CA 或客户端材料也不应被假定会自动加入草稿测试。需要对照时，可在当前草稿显式重新提供已获授权的材料，再独立测试已保存连接。

关闭或重置表单会使原测试结果失效；如果修改了连接参数，旧成功结果不能授权新参数。不要把窗口关闭理解为远端网络操作已经全部结束。

怎样理解状态和失败提示 ​

  • 正常 / 异常 / 未测试需要结合最近已保存测试摘要理解。测试时间是一次验证记录，不是持续健康监控。
  • 已停用 / 配置不完整先检查启用状态或必填参数；没有通用测试能力的类型应到工作台确认。
  • 草稿测试失败时，核对参数、认证、证书和目标可达性；不要将能建立 TCP 连接当作协议认证成功。
  • 如果提示连接已保存但验证未通过，先确认记录仍在，再修正配置并重测；不要直接重复创建同名连接。
  • Redis 的 PING 成功不证明 SCAN、读取或写入权限。Kafka 的元数据握手不证明主题样本可读，MQTT 连接成功也不证明目标订阅或发布可用。

排序与删除 ​

排序前清除搜索和类型筛选，并确保当前列表能完整展示全部连接。只有界面允许拖拽时才调整顺序，完成后刷新核对持久结果；筛选或分页状态下不要把当前局部顺序当作完整工程顺序。

删除只用于已经确认可丢弃的连接：

  1. 点击目标连接的删除操作，先查看引用影响。
  2. 有阻断引用时，先处理引用，不要绕过提示。系统接入源不提供编辑、删除操作。
  3. 选择取消应保留记录；确认删除后，核对目标连接已从列表消失。

删除连接不等于删除外部数据库或设备中的原始数据。界面提示保留并标记无效的数据点，也不等于全部关联配置自动迁移到了其他来源。

下一步 ​

数据库类连接可继续按使用 SQL 工作台查询并生成数据点核对查询、保存与真实 GET 的区别。

在所属工作台完成真实查询、Key 读取、请求或主题样本验证后，再检查生成的数据点及其开发态当前值。需要正式持续采集时，另行完成固定发布版本、部署、运行权限与断线恢复验证；不要把本页的连接测试结果作为运行态验收结论。
