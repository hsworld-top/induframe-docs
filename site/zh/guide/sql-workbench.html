使用 SQL 工作台查询并生成数据点 ​

本文说明如何运行一条测试查询、保存查询定义，再按需要生成一个数据点。工作台中的一次成功查询不是正式发布、持续采集或运行态权限验收。

开始前 ​

  • 已登录平台，有目标工程的数据中心开发与编辑权限，当前工程没有占用、过期或禁止开发的提示。
  • 已在接入源中准备好提供 SQL 工作台的连接。外部数据库账号需要实际查询权限；连接测试成功不代表业务表可读。
  • 如要尝试建表或写语句，只使用已确认可以丢弃的测试数据库和业务表。不要在生产数据、身份系统表或真实设备上试写。
  • 已确认当前连接的数据库类型、目标库和实际方言。不同数据库的函数、参数与结构操作能力不能互相套用。

进入工作台并运行查询 ​

  1. 在目标工程打开数据中心 → 接入源，找到连接并点击工作台。
  2. 先核对左上方的接入源名称。等待对象树和 SQL 编辑器加载完成，再输入语句；不要把加载中的占位当成可编辑区域。
  3. 使用新建查询创建空白标签，或从左侧树打开已经保存的查询。空白 SQL 不能运行。
  4. 输入适合当前数据库的查询，点击运行。
  5. 在下方结果表核对字段、行数和本次结果。失败时先处理错误，再运行一条已知正确的小查询确认恢复。

关系库中可先用下面的只读语句确认结果链路，不需要创建业务表：

sql
SELECT 42 AS sample_value;

对于要求从真实表查询的数据库，使用左侧表树的查询数据入口生成当前方言的语句，再核对目标表和范围。不要把关系库示例当作所有数据库均支持的语法。

格式化只改变当前 SQL 文本，不执行查询，也不代表语句已经保存。

使用值参数 ​

参数区显示当前方言对应的值参数。以 PostgreSQL 为例：

sql
SELECT $1::int AS sample_value;

在出现的参数输入框填写测试值，再点击运行。参数只绑定值，不能替代表名、列名或整段 SQL。测试值不会随查询定义保存，重新打开后需要重新填写。

保存查询并保护草稿 ​

  1. 点击工具栏的保存。首次保存时填写查询名称，再在弹出的保存查询窗口确认。
  2. 在左侧查询树确认名称，重新打开时按实际查询身份复用标签，不以标题相同判断是不同记录。
  3. 保存后的查询仍可继续编辑。编辑器获得焦点时，Ctrl+S（macOS 为 Cmd+S）使用同一个查询保存动作，不执行 SQL，也不生成数据点。
  4. 关闭带未保存修改的标签时，按提示选择保存后关闭或放弃修改。如要继续编辑，可用提示窗口的关闭按钮或 Escape 退出这次关闭操作。

保存请求只确认提交时的 SQL。保存期间继续编辑，新修改仍需要再次保存；不要因前一个请求成功就认为当前全文已经持久化。

运行与保存是两件事：运行不自动保存，保存也不会自动执行 SQL。

从查询生成一个数据点 ​

  1. 先运行查询，确认本次字段和值符合预期。
  2. 在右侧输出配置或数据预览中确认输出。默认输出为完整查询结果对象；需要单个值时，选择提取单个字段并检查字段选择。
  3. 点击保存并生成数据点。尚未保存的查询会先要求命名保存，再创建输出。
  4. 生成后，在数据预览中确认显示真实的数据点 GET 来源、路径与当前值；需要再次读取时点击刷新 GET。
  5. 修改提取配置后，使用保存并更新数据点确认新的输出配置。

每条查询在此界面维护一个输出。无行、缺少所选字段或无法提取时，先修正查询或提取配置，不要忽略禁用按钮旁的说明。

查询保存与输出保存分开

已有查询的保存并更新数据点保存的是输出配置，不会顺便保存未提交的 SQL。若修改过 SQL，先点击工具栏的保存，再核对数据点 GET 值。提示“GET 用的是已保存的 SQL”时，不能把旧定义读出的值当成当前草稿的执行结果。

未生成数据点时，右侧展示的是按本次 SQL 结果计算的预览。生成后的真实 GET 使用已保存定义；两种来源不同，不能仅凭值看起来一样就混为一谈。

表操作与结果范围 ​

  • 只有当前连接实际提供结构操作入口时才进行建表、修改或删除。系统内置身份表的保护不能通过直接执行 SQL 绕过。
  • 表菜单中的插入数据只生成一份可编辑模板，不会自动写入。运行前检查表名、字段、自增列和占位值，再明确点击运行。
  • 修改、删除或写入前先核对当前接入源与对象名；删除提示中选择取消，应保留原对象。
  • 下方结果分页只切换本次已经读取的结果，不会自动重新查询数据库。出现截断提示时，结果不完整；缩小字段、时间或行范围后重新运行。
  • 在较窄的窗口，右侧面板改为抽屉。用工具栏输出配置打开，用关闭右侧面板收起；不要把收起面板当成删除查询或数据点。

失败或慢查询时 ​

  • 对语法、缺对象和权限错误，先核对当前数据库、方言与授权，不要修改无关连接来掩盖问题。
  • 查询失败后，不把之前的成功结果当作本次结果。修正问题后重新运行，并核对新的反馈与数据。
  • 关闭标签或返回接入源不代表远端 SQL 已撤销。DDL、DML 或网络中断的提交状态不确定时，先由有权限者核实数据库实际状态，不要直接重复执行。
  • 不把保存查询、输出预览或一次真实 GET 当作正式发布后的持续运行验收。

下一步 ​

生成后到工程数据点中核对对应路径与开发态当前值。需要生产运行时，再独立完成发布、部署、运行授权和持续读取验证。
