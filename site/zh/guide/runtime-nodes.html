管理运行节点 ​

不清楚节点、运行环境和基础服务的关系时，先看运行环境与节点说明。

由组织管理员或运维人员进入 “运维管理” → “节点管理”。节点是实际服务器，先取得服务器负责人的授权，再安装、接入或调整归属。

服务器系统优先使用当前已测试的 Ubuntu 24，其他系统尚未测试；本页不因界面列出其他系统或架构选项就扩大验证范围。

1. 生成接入资料 ​

  1. 点击 “接入节点”。
  2. 填写可识别的节点名称和接入码有效期。
  3. 点击 “生成接入码”。
  4. 核对一次性接入码和节点可访问的中心地址，按页面保存。

接入码是敏感资料，不放进公开手册、截图、工单正文或源码。过期、已使用或无法查看时，先核对记录，再按需要重新生成，不重复分享旧码。

2. 在目标服务器安装 ​

从平台的 **“下载节点安装包”**选择与目标系统、CPU 架构一致的交付包。按页面及随包说明在目标服务器运行安装程序，粘贴本次接入码。

需要手动安装时，使用当前页面实际给出的连接地址和安装说明，不从其他环境抄一条命令。中心地址必须能被目标节点访问，不能把浏览器电脑上的 localhost 当成中心地址。

安装包完成不代表工程镜像、正式采集运行时或工程部署都已经准备好。

3. 核对接入申请与状态 ​

出现接入申请时，核对主机名称、地址和来源。确认是获准服务器后再点击“确认”，按对话框执行 “确认接入”；无法确认身份时先拒绝或联系负责人。

接入后检查：

  • 连接状态与最近心跳。
  • 节点类型、Agent 版本和实际地址。
  • CPU、内存、磁盘等资源使用。
  • 时间同步和运行底座、运行资格相关提示。

在线只表示连接层面的状态，不保证驱动能力、运行资格、容量和设备网络全部合格。

4. 关联运行环境或采集连接 ​

通过运行环境将节点关联到合适范围。工程部署和工业采集按各自条件选择节点，不能把节点加入环境等同于所有采集连接都已分配。

工业连接的落点和验证见工业采集说明。界面没有兼容节点时，先核对节点状态和能力，不更换协议绕过检查。

5. 取消分配与移除登记不同 ​

  • 取消分配：从某个运行环境移除关联，节点仍保留在中心登记中。
  • 移除运行节点：撤销中心登记与接入凭据，需要先满足环境和部署的清理条件。
  • 卸载节点本机程序：是另一项操作；移除登记不会远程自动删除本机程序和数据。

承载基础服务、工程或中心控制面的节点可能禁止取消分配或移除。先查明依赖、通知业务负责人，不绕过保护，也不直接删除服务器目录。

操作后到列表和运维记录确认结果，状态不明时先刷新，不连续提交移除。
